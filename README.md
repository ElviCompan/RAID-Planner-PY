# RAID Planner — планировщик DDP / LUN

Настольная программа: исходный пул дисков режется на группы DDP, в группе создаются LUN с типом RAID. Куски раскладываются сначала по ещё свободным дискам группы, затем по наименее заполненным.

## Запуск

Нужен Python 3.10 или новее (с Tkinter — он есть в обычном установщике Python для Windows).

В папке проекта:

```text
python raid_planner.py
```

План сам записывается в `%APPDATA%\RAID-Planner\autosave.json` и поднимается при следующем запуске. «Открыть…» / «Сохранить как…» (или Ctrl+O / Ctrl+S) — именованная копия того же JSON. Кнопка «Отчёт…» — HTML для печати в PDF, это не план.

## Что лежит в папках

| Путь | Зачем |
|---|---|
| `raid_planner.py` | Окно программы |
| `ddp/` | Расчёты без окна: RAID, раскладка по дискам, формат JSON. Нужен и программе, и проверкам. |
| `tests/` | Автопроверки расчётов. Их не открывают при обычной работе. |
| `raid_planner_e.py` | Старый черновик с RAID-6p/60, к этой программе не относится. |

## RAID-1

N-стороннее зеркало: 2, 3, 4 и более дисков. Полезная ёмкость как у одного диска, остальные — копии. Несколько зеркальных пар — это RAID-10.

## Проверка расчётов (тесты)

Это не часть ежедневной работы с планировщиком. Файлы в `tests/` прогоняют формулы RAID и раскладку без запуска окна: после правок кода можно убедиться, что «RAID-1 на трёх дисках по-прежнему даёт ёмкость одного диска», и что второй LUN садится на свободные диски, а не докладывается слева.

Один раз (из папки проекта):

```text
py -3 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
```

Потом, когда нужно проверить:

```text
.\.venv\Scripts\python -m pytest
```

Если в конце `passed` — расчёты совпали с ожидаемыми. Если `failed` — в выводе будет имя проверки и что именно разошлось. Саму программу это не запускает и планы не портит.
